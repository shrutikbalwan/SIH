## PARITY

Two deterministic vectors, expected values generated by the **desktop
TensorFlow reference + frozen INT8 model** *before* being embedded
(`tools/gen_selftest_vectors.py`):

| vector | source | expected q_out | expected detection |
|---|---|---|---|
| **lcg** | LCG generator, no waveform stored | **−126** | **NO** |
| **speech** | one real 16000-sample window (read-only) | **114** | **YES** |

Both outcomes are covered, so the self-test exercises a real detection and a
real rejection rather than only one branch.

The LCG is reproduced on device by identical integer arithmetic
(`state = state*1664525 + 1013904223`, `sample = (int16_t)((state>>16)&0xFFFF)`,
seed `0x12345678`), avoiding a second 32 KB waveform in flash. **Verified on
host: the C mirror produces `30019 -13008 9691 19292 -31522`, matching the
Python generator exactly.**

**Host parity: 1960/1960 INT8 features identical on BOTH vectors, max diff 0.**
Parity is asserted on the full feature plane, not merely on the final decision —
`main.cpp` requires `mismatch == 0 && q_out == expected && detection == expected`
for a vector to pass.

This is host evidence. It does not prove Xtensa parity: `-O2` on a different
compiler and FPU can reorder float operations. The on-device
`FEATURE_MATCH = x/1960` line is what will settle it.

## INVALID-AUDIO GUARD

Implemented in `ira_audio_guard.h/.cpp`, checked **before** feature extraction
and inference.

```c
bool ira_audio_window_valid(const int16_t pcm[16000]);
```

| condition | status | verified on host |
|---|---|---|
| all 16000 samples exactly zero | `IRA_AUDIO_INVALID_ALL_ZERO` → **false** | ✅ |
| all samples identical (non-zero) | `IRA_AUDIO_INVALID_CONSTANT` → false | ✅ |
| null pointer | `IRA_AUDIO_INVALID_NULL` → false | — |
| real speech window | `IRA_AUDIO_OK` → true | ✅ |

**Exactly-zero input returns `false`**, as required. When invalid, `main.cpp`
prints `RESULT = REJECTED_BEFORE_INFERENCE` and neither runs inference nor
reports a detection.

The constant-buffer case is justified on the same grounds as all-zero: a stuck
I2S line or latched DC produces a flat spectrum, the degenerate case that makes
the model misfire. It cannot reject legitimate speech, since real speech is
never bit-identical across 16000 consecutive samples.

**No general minimum-RMS threshold was chosen**, per instruction. Beyond the
instruction, there is a substantive reason to avoid one: the earlier diagnostic
found genuine missed detections were the *quietest* recordings (RMS 0.082 vs
0.137 for detected ones), so a naive RMS floor would discard exactly the cases
that already fail. Any broader guard must come from real microphone data.

## REMAINING ISSUES

1. **No ESP-IDF, no toolchain, no board.** Install ESP-IDF ≥ 5.1, then
   `idf.py set-target esp32s3 && idf.py build`. This is the blocking item.
2. **`ira_inference.cpp` and `main.cpp` are uncompiled.** Most likely first-build
   friction: `AddMean()` availability, the placement-new `MicroInterpreter`
   construction, and `TfLiteTypeGetName` linkage in TFLM 1.3.1.
3. **Tensor arena is an unmeasured 40 KB placeholder.** Trim once
   `ARENA_USED_BYTES` is observed.
4. **Xtensa parity is unproven.** Host parity is necessary, not sufficient.
   Do **not** enable `-ffast-math` — it would licence the reassociation that
   the double-accumulated mean/std specifically avoids (see
   `ESP32_FEATURE_PARITY_REPORT.md` §5.1). `-fno-fast-math` is set explicitly in
   `main/CMakeLists.txt`.
5. **Timing risk is unquantified.** 49 FFTs per 100 ms window on the generic
   backend may or may not fit. If it does not, the ESP-DSP swap is the first
   lever — and the parity harness must be re-run afterwards.
6. **Self-test flash cost ≈ 36 KB** from the embedded PCM vector. Fine for
   validation; drop `ira_selftest_data.cc` from `SRCS` for production builds.
